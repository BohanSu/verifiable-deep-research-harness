# 评分与证据充分度说明

## 1. 结论先行

系统当前展示的分数是用于控制 Agent 检索和停止策略的**透明启发式指标**，不是“结论为真的概率”，也没有经过统计校准。前端统一使用“证据充分度”“来源等级”等名称，不再使用容易造成概率误解的“可信度”。

系统对可靠性的主要保障不是单一分数，而是四道独立约束：

1. Evidence 中的 quote 必须是网页正文的逐字子串。
2. 同一结论优先要求不同 origin cluster 的来源互证。系统先合并规范正文完全重复和 SimHash 近重复页面，再读取 `rel=canonical`、Schema.org publisher/author、OpenGraph site name、citation/isBasedOn 与转载上游线索做保守同源合并，最后才按可注册域形成 fallback 簇；不同域仍只是弱独立性近似。
3. 不同年份或数值候选会进入冲突聚类和共识裁决。
4. 最终回答按中英文事实句执行 citation verification，核验器不得遗漏句子或擅自添加原回答未引用的 Evidence ID。

## 2. 来源等级

当前来源类型先验为：

| 来源类型 | 初始分值 | 含义 |
|---|---:|---|
| 官方候选 | 0.95 | URL/来源类型规则识别出的官方候选；未单独证明第一方身份 |
| 学术论文 | 0.90 | 可定位的论文或正式出版物 |
| 参考资料 | 0.82 | 百科、专业数据库等二手整理 |
| 一般网页 | 0.65 | 博客、媒体、聚合页面等 |

这些值是排序策略，不是经验概率，也不是网站真实性认证。来源类型主要由 URL 和页面信号启发式分类；它不能单独决定真伪：官方候选可能过时或并非第一方，论文可能被后续工作修正，一般网页也可能引用准确。因此系统还检查正文证据、来源独立性和冲突，并把 provenance 原始信号留给人工查验。

## 3. 单个回答目标的证据充分度

对每个 answer slot：

```text
slot_score =
    0.35 × 最高来源等级
  + 0.30 × 独立来源互证程度
  + 0.20 × 原文抽取一致性
  + 0.15 × 冲突解决状态
```

- 独立来源先使用规范 URL、规范正文哈希、SimHash 近重复、网页声明的 canonical/publisher/upstream 和可注册域分组，再统计 origin cluster。`dependent` 与同发布方证据不重复计数；`weak_host_fallback` 会明确展示“上游稿源未知”。网页元数据是来源自报信息，只能用于减少虚假独立计数，绝不能证明发布方身份或两个来源真实独立。
- 原文证据门同时要求 quote 能在抓取正文中逐字定位，检查 claim 中数字/年份是否全部出现在 quote、否定极性是否一致、英文词项或中文字符二元组覆盖是否达到阈值，并要求 claim/来源标题覆盖回答目标或子问题的核心概念。低目标相关性的 Evidence 不进入支持集合，不能填充候选答案。该规则能拦截部分扩大陈述、时间偷换和主题错配，但仍不代表完整语义蕴含概率。
- 反证查询只有在搜索成功、正文成功抓取并完成证据检查后才记为已执行；零结果和抓取失败不能通过该门。
- 冲突解决要求没有未裁决的显式反证；争议声明禁用权威单源例外，并使用 `min_independent_sources_for_contested_claim`。

## 4. 整体 Evidence Closure

```text
closure_score =
    0.35 × 必需回答目标覆盖率
  + 0.25 × 来源独立性
  + 0.20 × 原文逐字定位一致性
  + 0.10 × 来源等级
  + 0.10 × 冲突解决状态
```

分母是研究计划中 `required=true` 的回答目标数量；展示时应同时提供通过数/必需总数和每个分项的观测状态。若必需目标数量为零，分母无效，API 返回 `score=null, score_status=invalid`，不能把该状态渲染为 `0`。`threshold=0.75` 仅保留为历史诊断参数，不参与当前停止判定。所有 required slot 必须逐项通过来源、原文定位、反证检查和冲突裁决硬门；加权总分不能补偿任何失败硬门。

引用核验的分母是共享 claim parser 从最终回答解析出的预期句单元数；缺少该分母时显示“未记录”，不能用已有 item 数量补齐。Token、费用、页面覆盖率和事件顺序同样必须区分“观测到的零”和“未记录/不适用”。

## 5. 当前依据与局限

有依据的部分：

- 可追溯引用、独立来源互证、冲突检查和逐句蕴含验证是事实核验与检索系统中的常见工程原则。
- BrowseComp 和 GAIA 支持分别评估长程检索与多工具任务完成能力。
- Evidence Closure 的思想与项目已有 PEARL semantic-closure 经验一致，适合控制“继续检索还是停止”。

尚未获得实证依据的部分：

- 各项权重和来源先验尚未在标注数据上拟合。
- LLM 输出的 extraction confidence 未被解释为概率。
- 近重复与网页 provenance 元数据可以识别部分转载、共同 canonical 和自报同发布方，但元数据可缺失或伪造；不同域名、深度改写、未声明的共同通讯社稿源或同一组织多品牌仍可能被误判为独立。
- 当前可注册域计算使用内置常见二级后缀表，不等价于完整 Public Suffix List。
- citation verifier 自身也可能产生判断错误，需要人工标注集评估。

## 6. 正式实验中的校准方案

在汇报中若要把分数提升为有实证支撑的置信估计，应完成：

1. 从 BrowseComp/GAIA 和自建冲突集抽取至少 100 至 300 个 claim-evidence 对。
2. 人工标注 `supported / partial / unsupported`、来源类型和是否独立。
3. 报告 citation verifier 的 precision、recall、F1 和混淆矩阵。
4. 对 slot score 报告 Brier Score、ECE 和 reliability diagram。
5. 使用 held-out validation set 调整权重，或使用 logistic/isotonic calibration。
6. 正式测试集只使用冻结后的权重，不在测试结果上调参。

完成上述校准前，论文和 PPT 应始终称其为“evidence sufficiency score”，不能称为“truth probability”。
