## AG-UI 本轮适配结论

- 外部恢复使用新的 AG-UI `runId`；内部继续恢复同一个 durable checkpoint。
- `interruptId` 改为 `int:v1:<opaque random token>`，只通过服务端 SQLite 映射定位 durable run，不把内部 run ID 暴露给客户端。
- `resume[]` 必须覆盖同一 `threadId` 的完整 open interrupt 集合。
- `resolved` payload 必须满足 interrupt 的 `responseSchema`；费用不确定重试还必须显式确认。
- payloadless `cancelled` 会原子消费中断、写入 receipt，但不修改 checkpoint，也不启动 research worker。
- 可选 `parentRunId` 只校验产生 interrupt 的外部运行谱系并写入 receipt；恢复关联仍以 `interruptId` 为准。
- interrupt 前发送 `STATE_SNAPSHOT` 和 `MESSAGES_SNAPSHOT`。官方 SDK 验证后的完整输入消息及原消息 ID 会私有持久化并在恢复时回放；ResearchEngine 当前仍只把最后一条用户消息作为研究问题。

## 明确限制

- ResearchEngine 当前每个终态只生成一个可操作 interrupt，尚未生成并行异构 interrupt；入口和事务层已经按完整集合处理，为后续扩展保留正确约束。
- 浏览器 `GET /stream` 是项目自定义 SSE，不属于 AG-UI 适配器。
- AG-UI 输入中的共享 `state`、客户端 tools 和 context 尚未进入研究引擎语义；完整消息会保留，但尚未参与多轮推理。
- 服务仅监听 loopback，没有互联网多租户身份系统；当前授权边界是 `threadId + open interrupt record + exact receipt transaction`。
- 官方没有独立 AG-UI conformance CLI。本项目只声明固定 SDK 版本上的验证适配，不声明完整协议认证。
