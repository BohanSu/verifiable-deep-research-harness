# 六智能体研究系统自我反思与改进记录

更新时间：2026-07-19
目的：记录独立审查角色发现的漏洞、可复现反例、修复责任和验证证据。本文不把“设计上应该如此”当作“当前运行已经如此”。

## 1. 证据等级

| 等级 | 含义 | 可用于什么结论 |
|---|---|---|
| `E0` | 设计意图或候选方案，尚无运行证据 | 只能说明计划，不可称已实现 |
| `E1` | 静态代码、schema 或单元测试证据 | 可称局部实现，不能证明端到端行为 |
| `E2` | 集成测试、故障注入或真实 HTTP/SDK 验证 | 可称边界已验证，但仍受测试范围限制 |
| `E3` | 带持久化运行产物、输入、版本和复现命令的真实运行 | 可复核具体运行，不外推到所有任务 |
| `E4` | 冻结数据集、标注协议、重复实验和统计报告 | 才能支持 benchmark 或校准性结论 |

## 2. 第一轮独立审查

本轮并行角色：人因与信息架构、协作真实性、证据与量化、协议与框架官方资料、安全与恢复。每个角色独立读取代码和文档；审查结论先进入 `open`，只有修复后重新测试才能改为 `verified`。

### 2.1 人因与前端

| 状态 | 发现 | 反例/影响 | 修复要求 |
|---|---|---|---|
| `in-implementation` | 硬门汇总按数量而不是必需 `slot_id` 对齐 | 可选目标或缺失目标审计可能被显示成 `2/2`、`5/5` | 以必需目标 ID 集合计算分子分母，缺失记录显示为未审计 |
| `in-implementation` | 旧历史状态缺数组时，局部渲染异常可能阻断后续证据和回答 | 历史运行只因字段版本旧就无法人工复核 | 所有历史字段先规范化；不可验证字段局部降级 |
| `in-implementation` | Evidence ID 解析格式过窄 | `E-evidence` 等合法持久化 ID 无法点击，用户误以为没有引用 | 依据当前 Evidence ID 精确解析，未知 ID 显式标为失效引用 |
| `in-implementation` | 摘要机械截断可能截掉引用 | 无引用半句被误显示为完整结论 | 按完整句与引用一起截取；否则标记为回答节选 |
| `in-implementation` | 钻取按钮没有稳定定位、聚焦和播报 | 用户点击“核查”后仍不知道具体事实在哪里 | 统一展开、滚动、聚焦、live-region 通知 |
| `in-implementation` | 继续补证缺少预算和费用确认 | 用户不清楚恢复节点、增量预算和潜在费用 | 请求前展示缺口、恢复节点、当前/新增上限和确认动作 |
| `open` | SVG 外层 `role=img` 与内部可聚焦节点语义冲突 | 屏幕阅读器可能看不到关系图交互节点 | 提供同步可访问节点列表，并区分全局概览与可读交互视图 |
| `open` | invocation/事件视图截断但没有说明 | 用户把“最近 18 条”误认为完整历史 | 显示最近 N/总数、全局序号和完整主时间线入口 |
| `open` | 首页历史加载失败与空历史混为一谈 | 网络故障被误读为没有历史记录 | 区分 loading、empty、error，并提供重试 |

### 2.2 协作真实性与持久化

| 状态 | 发现 | 反例/影响 | 修复要求 |
|---|---|---|---|
| `in-implementation` | fresh search/fetch 没有独立真实 invocation | 产物被挂到最近 Scout 调用，无法回答“哪次调用访问了哪篇文章” | 为能力调用记录子 invocation，并用显式 parent 关联 |
| `in-implementation` | receipt 目前可能只凭字符串匹配成立 | ghost invocation、错误 consumer 或错误 run 可能被画成已消费 | 校验 envelope、run、consumer invocation、输入 artifact 和时间顺序 |
| `in-implementation` | artifact checksum 没覆盖 manifest 元数据且可覆盖 | producer、父产物或 message 绑定可被改写，审计链断裂 | 不可变 manifest + metadata hash + producer/message/parent 绑定；父产物缺失 fail-closed |
| `in-implementation` | 同一幂等 key 的 started operation 有并发双发窗口 | 两个 provider 请求都可能产生费用，最终结果只保留一个 | 第二调用返回 in-progress；只有过期 owner/fence 条件成立才允许 retry |
| `in-implementation` | operation 已完成但 checkpoint 尚未写入时，恢复只留下 replay | 真实副作用看起来像未执行或被误记为 replay | 持久化 original invocation，replay 必须引用 original |
| `open` | `parent_invocation_id` 未表达真实因果 | 日志相邻被误当成角色交接，无法表示 fan-in/fan-out | 增加可校验 causal edge，不用相邻数组推断因果 |
| `open` | resume receipt、worker lease、worker completion 不是同一状态机 | 完成后的 receipt 重放可能再次启动 worker | 只有未完成且 lease 过期时允许 reclaim |

### 2.3 安全与恢复

| 状态 | 发现 | 反例/影响 | 修复要求 |
|---|---|---|---|
| `in-implementation` | URL 只做一次 DNS 解析校验 | DNS rebinding/重定向可能把请求导向内网 | 每跳固定已校验地址或校验实际 peer，禁止 TOCTOU |
| `in-implementation` | 普通 API GET 的读边界弱于 mutation | 跨站读取运行状态，未知 run GET 还可能创建目录 | 所有 API 统一读写边界；未知 run 只读不得创建资源 |
| `in-implementation` | DeepSeek redirect 可能携带 Authorization | 302 到其他 origin 时 API key 泄漏 | 固定 HTTPS origin，跨 origin/降级 redirect 清除凭据 |
| `in-implementation` | A2A app 层缺少可信 Host/Origin 和 run namespace 隔离 | task ID 可与 Web run 冲突，跨协议争用同一 durable run | app 级边界、独立 task namespace、统一 lease/fence |
| `open` | `"false"` 等字符串可能被当作 ambiguous retry 确认 | 恶意或错误客户端绕过人工确认 | 严格要求 JSON boolean，并设置累计预算上限 |
| `open` | interrupt 扫描失败可能 fail-open | DB 锁/损坏时新任务绕过恢复顺序 | 扫描错误返回 409/503，不启动新任务 |
| `open` | heartbeat 异常未必会取消旧 worker | 新 worker reclaim 后旧 worker 仍可能访问付费 provider | heartbeat 失败即标记 lease lost、取消并禁止非幂等重试 |
| `open` | 上游响应、PDF 输出和事件尾部读取缺少统一资源上限 | 大响应或超长事件历史造成内存/CPU 消耗 | 所有外部 body、解析输出和分页读取硬上限 |

## 3. 量化审查边界

当前 `evidence-closure-v4.18` 分数是透明启发式，不是事实真伪概率。审查必须分别报告：

1. 观测值：分子、分母、来源 ID、origin cluster、quote 定位结果和反证执行记录。
2. 决策门：哪些条件必须全部满足，哪些分数只用于排序。
3. 证据局限：不同域名不是机构独立证明，网页 provenance 是自报信号，claim-quote 规则不是完整语义蕴含。
4. 校准缺口：没有人工标注集和 held-out 评测前，不得把 `0.95`、`98%` 或 `通过` 说成概率。

当前 `runs/` 中可直接复算的完成样例主要是 `MockModelProvider + ReplaySearchProvider`。任何“真实 DeepSeek/真实搜索端到端成功”的陈述，必须同时提供 run ID、运行时 provider、输入问题、版本、计费记录和 source snapshot；缺少这些字段时降级为历史人工观测，不作为当前可复核证据。

## 4. 官方协议核验规则

每个协议选型必须同时记录：上游官方 URL、查询时间、上游版本/规范、本机解释器与安装版本、实际验证命令、未覆盖能力和重新评估触发条件。所谓“上游当前版本”只能写成带时间的版本快照，不能暗示应用启动时会在线查询，也不能替代 lock/constraints。A2A、MCP、AG-UI、LangGraph、smolagents、OpenTelemetry/W3C 的版本号不能互相替代能力证明。

状态词只允许以下四种：

- `current-runtime`：当前默认执行路径，已有本项目测试或持久化运行证据。
- `validated-adapter`：在指定官方 SDK/客户端版本上验证过的有限适配，不代表完整 conformance。
- `adapter-blocked`：目标仍成立，但被依赖冲突、缺失外部资产或尚未实现的必要语义阻断。
- `candidate`：完成一手资料调研但未安装、未导入、未接入；候选能力不得画成当前执行路径。

- A2A 适合独立部署的 opaque Agent 任务互操作；不自动意味着同进程六角色应该 HTTP 化。
- MCP 适合工具/资源边界；不自动意味着 Planner/Critic/Writer 应注册为 MCP tools。
- AG-UI 适合 Agent backend 到前端的生命周期和事件流；协议传输无关，项目只验证了一个 POST JSON/SSE profile，自定义 GET SSE 不能改名为完整兼容。
- A2A、MCP、AG-UI POST 当前都是固定边界的有限 `validated-adapter`；AG-UI live harness 已补齐 success/interrupt、resolved/cancelled resume、durable 复用、幂等重放、消息快照、schema/顺序和负例证据。三者都必须同时写明 binding/transport、SDK 快照、实际方法和未覆盖能力；AG-UI 仍不宣称覆盖完整事件、传输、state/tools/context 语义或正式认证。
- LangGraph `1.2.9` 的 checkpoint、interrupt、durable execution 是 `candidate`，不能写成当前已使用的 runtime，也不能假定自动替代 operation ledger、副作用幂等和 lease/fence。
- smolagents `1.26.0` 的 CodeAgent/ToolCallingAgent 是 `candidate` baseline；当前未安装，代码执行必须有真实沙箱，`LocalPythonExecutor` 不能作为安全边界。
- OpenTelemetry SDK、GenAI/MCP semantic conventions 和 W3C Trace Context 是保留的 `candidate` 观测目标；当前没有依赖、span、exporter 或 `traceparent`/`tracestate` 传播，应用 `run_id` 不是 W3C trace 证明。
- Python 3.14 的 `[mcp]` 依赖已改为条件化 Starlette 范围；本机仍未运行 Python 3.14，因此只能记录为未验证，不能把依赖解析写成运行支持。

## 6. 2026-07-20 第二轮独立复核

本轮重新启动两名独立审查角色：一名只读检查协议状态、A2A TaskStore、MCP 边界和版本证据；另一名只读检查恢复链路、handoff 真实性、来源图和无障碍展示。审查结果逐项回到当前源码与测试，而不是直接把报告标为漏洞。

| 复核项 | 当前结论 | 证据与处置 |
|---|---|---|
| AG-UI resume 文档相互矛盾 | `verified`（有限路径） | 2026-07-20 重新运行 `npm test --prefix conformance/agui -- http://127.0.0.1:8767`；success、interrupt、resolved/cancelled resume、durable 复用、同 runId 幂等重放、消息快照、schema/顺序和负例均通过。文档已统一为 pinned finite `validated-adapter`，仍不宣称完整协议。 |
| AG-UI/协议索引终态回退 | `verified` | `protocol_index.py` 有状态枚举、合法迁移表、终态 self-loop、SQLite transition ledger 和未知状态 fail-closed；禁止 completed 回到 queued。 |
| A2A ListTasks 过滤前截断 | `verified` | `a2a_task_store.py` 使用 owner/过滤条件下推、SQL keyset cursor、过滤指纹和旧 cursor 迁移；`MAX_A2A_TASK_LIST_SCAN` 仅保留兼容名称，不再作为扫描上限。 |
| 恢复审计不一致仍展示答案 | `verified` | `effectiveRunStatus()` 产生 `recovery_unverified` 后，结果摘要和回答正文隐藏，仅展示恢复审计入口；普通终态不会绕过 fence/receipt 检查。 |
| 旧 invocation 缺少消费字段被误判 | `verified` | 规范化过程区分“字段缺失”和“明确空数组”，仅在原始字段确实存在时校验 `consumed_handoff_message_ids`。 |
| 查询节点无法打开所有关联文章 | `fixed` | 关系图已有规范化 query association；本轮修复 inspector 使用同一 `sourceQueryIndices()`，支持 query ID（若存在）和大小写/空白规范化文本，不再用原始字符串精确匹配。 |
| 查询/文章/证据关系可审计 | `verified` | 图谱使用 query → source → evidence → target 的有向边；文章旅程展示全部关联查询、读取模式、fetch invocation、快照和来源簇；缺失字段显示不可验证而不是补零。 |
| 人类可理解的完成度/可信度 | `verified with limits` | 页面展示分子/分母、观测来源、硬门作用和“非事实概率”警告；来源独立性、网页 provenance、quote 规则和 provider 用量均保留限制。没有标注数据前不把启发式分数称为概率。 |

本轮官方网络复核结果（PyPI/npm 与协议官网）：A2A `1.1.1`、MCP `1.28.1`、AG-UI Python `0.1.19`、AG-UI TypeScript `0.0.57` 未发生版本漂移；A2A 官网仍显示稳定规范 1.0，MCP `latest` 仍指向 `2025-11-25`，AG-UI 架构仍强调 backend-to-frontend 事件边界。该结果只更新版本快照，不替代锁文件或完整协议认证。

本轮仍保持开放的设计项：Python 依赖范围尚非 lock；AG-UI `state/tools/context` 尚未进入 ResearchEngine 语义；thread-wide 多 durable run 中断扫描尚未与单 run checkpoint 形成跨库原子事务；MCP adapter 的安全声明仍依赖默认 web provider 的 SSRF/重定向/socket pinning 实现；LangGraph、smolagents、OpenTelemetry/W3C 仍是候选，不得画成当前运行时。

## 5. 修复后的通过标准

- 所有 P0/S1 问题都有负例测试；不能只增加成功路径测试。
- 后端持久化事实与前端展示使用同一字段，前端遇到旧字段不会整页中断。
- 每个“已验证”标签都能回到测试、运行产物或官方一手记录。
- 真实运行、Mock/Replay、设计候选和外部依赖在 UI 与文档中有不同状态标识。
- 第二轮独立审查必须确认第一轮反例不再成立；否则保持 `open`，不宣称目标完成。

## 7. 2026-07-20 协议回执与前端故障复核

第三轮复核把“安装版本匹配”和“适配器已经验证”拆成两个独立问题。`system_contract.py` 现在只有在协议版本、SDK 版本、命令、有效期和证据文件 SHA-256 全部匹配时才返回 `validated-adapter`；没有回执、回执过期或版本漂移统一返回 `adapter-blocked`，而不是沿用旧的 `installed-but-unverified` 静态标签。当前三份回执对应的证据束为 `conformance/protocol-validation-evidence-20260720.txt`。

本轮还确认了四个边界：AG-UI 缺失 `runId` 直接拒绝；A2A 的同 Task `input-required` 恢复仍是明确 capability gap；MCP 的 SSRF 保护只属于默认网络 provider，custom provider 必须声明并执行自己的 URL 校验；OTel SDK、GenAI/MCP semantic conventions 和 W3C Trace Context 仍是候选观测目标，不能由应用 `run_id` 代替。

前端复核新增了三类故障保护：坏 SSE JSON、半开无事件连接和轮询 HTTP/JSON 暂时失败都会切换到带退避的轮询，不把网络故障伪装为研究失败；未知后端状态显示为“运行状态待确认”，不直接泄漏机器枚举；审计续页在加载期间暴露 `aria-busy`，并将焦点恢复到续页控件或审计容器。分页窗口、协议状态、证据覆盖和可信度均继续采用“分子/分母 + 硬门 + 证据来源”的可核查表达，不把启发式分数当概率。
