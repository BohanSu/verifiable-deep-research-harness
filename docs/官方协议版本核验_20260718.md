本记录只采用协议官网、官方代码仓库和官方包注册表。2026-07-20 复核查询时间为 `11:01 CST`（`2026-07-20 03:01 UTC`）。本轮通过 PyPI/npm 官方 JSON 注册表查询，并读取协议/框架官方文档；这里的“上游版本”是查询时刻的官方版本快照，不是应用启动时的在线检查，也不是依赖锁；它必须与本机解释器、安装版本和实际验证范围分开阅读。

状态词统一为：`current-runtime` 表示当前执行路径；`validated-adapter` 表示指定官方 SDK 下验证过的有限适配；`installed-but-unverified` 表示包已安装但版本不在验证证据覆盖范围；`not-installed` 表示期望包不在当前解释器；`adapter-blocked` 表示目标保留但当前存在明确阻断；`candidate` 表示已调研但未安装、未导入、未接入。

## 2. Agent 间协议选择

### 为什么继续选择 A2A

- A2A 官方仓库将其定义为不同框架、不同组织、不同服务器上的 opaque agentic application 之间的开放互操作协议，覆盖 Agent Card、长任务、流式和异步协作。
- A2A 已进入 Linux Foundation 治理，当前稳定规范为 1.0，官方 Python SDK 与本项目版本一致。
- IBM/BeeAI 的 ACP 官方仓库明确写明“ACP is now part of A2A under the Linux Foundation”，并链接到官方合并公告。仓库中的历史迁移指南链接在本次复核时已失效，因此不把该指南的可用性作为选型依据。ACP 不再适合作为与 A2A 平行的新核心依赖。
- MCP 解决 Agent/模型到工具与资源的连接，不替代 Agent-to-Agent 任务生命周期；AG-UI 解决 Agent backend 到交互前端的事件流，也不替代 A2A。

### 为什么内部六角色不使用 A2A

当前 Planner、Scout、Curator、Critic、Writer、Verifier 位于同一进程并共享 durable run。对它们使用 HTTP A2A 会人为增加网络、身份、序列化和分布式恢复失败面。项目仅将完整 ResearchEngine 暴露为一个 A2A Agent；内部协作使用项目私有、类型化、可持久化的 route envelope，并明确区分“计划投递”与“接收回执”。

## 3. 本项目已验证范围

- A2A：官方 SDK Agent Card、SendMessage、GetTask、ListTasks；A2A 1.0 over JSON-RPC 2.0、非流式、无 push；SQLite TaskStore 重启恢复。
- MCP：官方 `ClientSession` stdio initialize、tools/list、search/fetch、分页、正文不可信标记。MCP adapter 只验证输入边界；SSRF、逐跳重定向检查与连接地址 pinning 由默认 web provider 提供，replay/custom provider 需单独验证。ResearchEngine 当前直接调用 provider，不经 MCP。
- AG-UI：Python SDK 类型构造；TypeScript `transformHttpEventStream + verifyEvents` 解析真实 HTTP SSE；固定 harness 已覆盖 success/interrupt、opaque interrupt、response schema、消息快照、parent lineage、resolved/cancelled resume、durable checkpoint 复用、同 runId 幂等重放、事件顺序和负例。该结论只验证有限适配路径，不覆盖全部事件、传输 profile、state/tools/context 多轮语义或正式认证；完整消息会持久化/回放，但当前只有最后一条用户消息进入 ResearchEngine 问题语义。

这些测试不证明 A2A 全绑定、MCP 全能力或 AG-UI 正式 conformance。浏览器 `GET /api/runs/{id}/stream` 仍是 `current-runtime` 的项目自定义 SSE；A2A/MCP/AG-UI POST 都只在各自固定边界内标记为有限 `validated-adapter`，完整 AG-UI 语义和正式认证仍未覆盖。

## 4. 版本与兼容性边界

- `pyproject.toml` 现在对已验证的直接适配器固定为 `ag-ui-protocol==0.1.19`、`mcp==1.28.1`、`sse-starlette==2.4.1`、`a2a-sdk[http-server]==1.1.1`；`[mcp]` 按解释器精确选择 `starlette==0.38.6`（Python `<3.14`）或 `starlette==0.48.0`（Python `>=3.14`）。这消除了直接协议包的范围漂移，但项目仍没有 Python lock/constraints 文件，传递依赖和 build-system 仍由 resolver 选择，因此不能声称字节级环境可复现。
- “本机版本”特指 `/opt/miniconda3/bin/python`（CPython `3.13.9`）的查询结果；其他 `python3` 解释器不能沿用该结论。
- Python 3.14 的 `[mcp]` extra 已使用条件化精确 Starlette pin；由于本机未运行 Python 3.14，仍不宣称该环境已验证。
- `/api/system-contract` 中的上游版本和 `checked_at` 是代码内版本快照；它只动态读取服务器解释器中的 Python installed version，不执行在线上游查询，也不动态检查 npm lock。TypeScript 的 `package.json` 与 `package-lock.json` 是独立的 checked-in 证据，文档和 UI 应使用“官方版本快照，核验于……”而不是“实时最新版本”。
- LangGraph、smolagents、OpenTelemetry/W3C 均不在当前依赖或执行路径中；记录版本是为了维护候选决策，不是能力证明。

## 5. 最新运行边界

- execution lease 使用 owner token、单调 fence、TTL 与 heartbeat。
- checkpoint、outbox、operation ledger、usage、final.json 和 source snapshot 的 execution worker 写入均在 SQLite `BEGIN IMMEDIATE` 事务中校验当前 owner/fence。
- lease 过期后可从非终态 durable checkpoint 取得更高 fence 恢复；ambiguous 非幂等付费 operation 仍禁止自动重试。
- JSONL outbox 是带文件锁和修复能力的投影，不是分布式消息队列。
- 系统仍是单机、每 run 本地 SQLite/文件系统设计，没有多主机共识、共享文件系统锁语义或互联网多租户身份层。
